# Reminder REST Service

**Reminder** — REST-сервис для управления личными напоминаниями. Пользователь может создавать, редактировать, удалять и искать напоминания. В назначенное время сервис отправляет уведомление на email.

**Стек:** Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA, PostgreSQL, Liquibase, Quartz, Spring Mail.

## Аутентификация и безопасность

Сервис работает как **OAuth2 Resource Server**. Авторизация пользователей и выдача JWT выполняются отдельным `auth-service`.

- JWT проверяется по публичному RSA-ключу (RS256), а также по `iss`, `aud` и сроку действия.
- Из токена извлекаются ID пользователя и email.
- Пользователь имеет доступ только к собственным напоминаниям.
- Сессии не используются, API работает по принципу STATELESS.
- Swagger/OpenAPI и health-check доступны без авторизации.

### Как настроен Auth-сервис. Настройка Google OAuth2

Для аутентификации через Google в [Google Cloud Console](https://console.cloud.google.com/auth/clients) был создан OAuth2-клиент `reminder-auth-service` типа **Web application**.

Получены `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.

В разделе **Authorized redirect URIs** указан адрес:
```
http://localhost:8082/login/oauth2/code/google
```

## Работа со временем

Для создания напоминания передаются локальная дата, время и часовой пояс в заголовке `X-Timezone`. По умолчанию используется `Asia/Almaty`.

Время преобразуется в `Instant` и сохраняется в PostgreSQL как `TIMESTAMPTZ`. При получении напоминаний время отображается с учётом часового пояса пользователя.

Поддерживаются поиск по дате и диапазону дат, проверка времени на корректность и запрет создания напоминаний в прошлом.

## Планирование и отправка уведомлений

Для планирования отправки писем используется **Quartz с JDBC Job Store**.

- Задания и триггеры хранятся в PostgreSQL и сохраняются после перезапуска приложения.
- При изменении напоминания расписание обновляется, при удалении — соответствующее задание удаляется.
- Изменения напоминаний и заданий Quartz выполняются в рамках одной транзакции благодаря общему DataSource.
- При ошибке отправки письма предусмотрены повторные попытки через Quartz. По умолчанию — три попытки с увеличивающейся задержкой.

## Идемпотентность

Для POST и PATCH реализована идемпотентность через заголовок `Idempotency-Key`.

- Повторный запрос с тем же ключом не создаёт новую операцию, а возвращает текущее состояние связанного напоминания.
- Для защиты от конкурентных запросов используются PostgreSQL Advisory Locks и уникальное ограничение в БД.
- Ключ привязан к пользователю. Для каждой новой операции необходим новый ключ.
- Записи идемпотентности автоматически удаляются через 24 часа.

## Дополнительно

- **Liquibase** — управление схемой БД, включая таблицы Quartz.
- **SpringDoc OpenAPI / Swagger UI** — документация и тестирование REST API.
- **Spring Boot Actuator** — мониторинг состояния приложения.
- **Clock** — управление временем в тестах.

Сервис рассчитан на запуск одного экземпляра Quartz. Для горизонтального масштабирования потребуется дополнительная настройка кластеризации.


## Основные методы API

Все пути в таблице указаны относительно `/api/v1/reminder`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/` | Создать напоминание (`201`) |
| PATCH | `/{id}` | Частично изменить напоминание (`200`); поля со значением `null` не изменяются |
| DELETE | `/{id}` | Удалить напоминание и его Quartz-задание (`204`) |
| GET | `/?title=текст` | Поиск по части названия без учёта регистра |
| GET | `/sort/title` | Список с сортировкой по названию |
| GET | `/sort/date` | Список с сортировкой по времени |
| GET | `/search-by-date?date=2030-06-15` | Напоминания за локальный день |
| GET | `/filter/date?start=2030-06-15T00:00:00Z&end=2030-06-16T00:00:00Z` | Напоминания за диапазон времени |

Для корневых POST и GET используйте `/api/v1/reminder` без завершающего `/`. Списки поддерживают `page`, `size`, `sort`; нумерация страниц начинается с нуля. Также есть вспомогательный `POST /addsomereminders`, создающий два тестовых напоминания для текущего пользователя.

Пример тела создания (нужны заголовки `Authorization`, `Idempotency-Key`, `Content-Type: application/json`; `X-Timezone` необязателен):

```json
{
  "title": "Позвонить",
  "description": "Обсудить планы на неделю",
  "remind": "2030-06-15T18:30:00"
}
```

## Локальный запуск

Для запуска проекта необходимы Docker и Docker Compose. Основные настройки находятся в `application.yaml` соответствующих сервисов.

1. Добавьте приватный RSA-ключ `jwt-private.pem` в каталог `secrets` для работы сервиса аутентификации.
2. Заполните файл `.env`, указав Google OAuth2 credentials и настройки SMTP для отправки писем.
3. Из корневого каталога проекта выполните:

   ```bash
   docker compose up -d --build
   ```

Docker Compose соберёт образы и запустит сервисы. PostgreSQL поднимается в контейнере, миграции Liquibase выполняются автоматически при запуске приложения.

**Полезные ссылки:**

- REST API — `http://localhost:8080`
- Swagger UI — http://localhost:8080/swagger-ui/index.html
- Health Check — http://localhost:8080/actuator/health
